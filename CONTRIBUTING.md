# Contributing to Mazic

Thank you for your interest in contributing to Mazic! We welcome contributions from mages of all skill levels. This document outlines the process for contributing to our magical labyrinth.

## Getting Started

1. Fork the repository:
   ```
   git fork https://github.com/hjamet/Mazic.git
   ```

2. Clone your fork:
   ```
   git clone https://github.com/your-username/Mazic.git
   ```

3. Create a new branch for your feature or bug fix:
   ```
   git checkout -b feature-name
   ```

## Making Changes

1. Make your changes in your feature branch.
2. Write or update tests as necessary.
3. Ensure your code follows our coding standards (see below).
4. Run the tests to make sure everything still works.

## Commit Guidelines

We follow the [Conventional Commits](https://www.conventionalcommits.org/) specification. Please format your commit messages accordingly:

```
<type>[optional scope]: <description>

[optional body]

[optional footer(s)]
```

Common types include: feat, fix, docs, style, refactor, test, and chore.

## Submitting Changes

1. Push your changes to your fork:
   ```
   git push origin feature-name
   ```

2. Open a pull request against the `main` branch of the Mazic repository.
3. Provide a clear description of the changes in your pull request.
4. Link any relevant issues in the pull request description.

## Code Standards

- Use [Google-style docstrings](https://sphinxcontrib-napoleon.readthedocs.io/en/latest/example_google.html) for all functions and classes.
- Include type hints as per [PEP 484](https://www.python.org/dev/peps/pep-0484/).
- Write clear, self-explanatory code with meaningful variable and function names.
- Comment your code where necessary, but prefer self-documenting code.

## Testing

- Write unit tests for new functionality.
- Ensure all tests pass before submitting a pull request.
- Aim for high test coverage, especially for critical parts of the codebase.

## Documentation

- Update the documentation when adding or modifying features.
- Use clear and concise language in all documentation.

## Community

- Be respectful and considerate in all interactions.
- Help review pull requests from other contributors.
- Participate in discussions on issues and pull requests.

## Questions?

If you have any questions about contributing, feel free to open an issue for clarification.

Thank you for contributing to Mazic. Together, we'll create an enchanting experience for all who enter our magical labyrinth!
